# Headless session spike (Linux only)

This is an isolated local prototype, not a production terminal/session manager.
It uses the exact published `jterm_engine@57ed89a` parser, screen and local VT
semantic dispatcher. No byte parsing is performed in JavaScript.

## API

- `Terminal::new(rows, cols)` admits at most 128 × 256 cells.
- `feed(bytes)` accepts up to 64 KiB and returns protocol reply bytes.
- `resize`, `frame() -> CellFrame`, `visible_text`, `unsupported_count`.
- Linux `Session::spawn(rows, cols)` starts fixed `/bin/sh -i` with `TERM=dumb`.
- `write(bytes)` accepts at most 4 KiB and returns the accepted byte count;
  **the caller must retain and retry the unaccepted suffix**.
- `poll()` is nonblocking, reads at most 64 KiB, flushes bounded protocol replies,
  and observes direct-shell exit. Input generated by a user goes to the shell;
  no shell command is inferred from output or external content.
- `resize`, `close` (idempotent handoff), `cleanup_pending`, `terminal`, `is_exited`.

## Explicit limits

There is no scrollback/reflow, complete OSC policy, Kitty graphics,
IME composition, combining grapheme storage, selection or rendering code.
Unhandled events and zero-width combining marks increment an explicit counter.
Unicode scalar width uses unicode-width 0.2.3; this is not yet parity-audited
against the existing terminal width policy.

The adapter owns/reaps **only the direct shell**. Closing the PTY descriptors and
asynchronously terminating/reaping the shell is not proof of descendant/session containment. A
production adapter must reuse the existing reviewed PTY lifecycle and process
ownership protections before full shell use. This experiment must not replace
that implementation or claim shutdown safety for background processes.

The consumer must authorize session identity, focus and input ownership; this
crate alone has no multi-window authority. A caller must poll and retain output
until drained; shell exit does not mean all buffered output was consumed.

### Drain and writer failure contract

`is_exited()` only means the direct shell was reaped; it is **not** a final-frame
signal. Continue `poll()` until `is_drained()` (exit plus read EOF/Linux PTY EIO).
Each poll drains at most 64 KiB and performs at most 64 reads, including interrupted
reads. Descendants retaining the slave can delay EOF indefinitely; this spike still
does not own the descendant process tree.

Writes retry EINTR up to eight times, then report zero progress. A partial result
always leaves the suffix with the caller. Fatal writes (including zero-byte writes
of nonempty data) disable further writes, but never block polling final output.
Check the sticky `write_error()` separately: `poll()` may succeed while the writer
has failed. Pending protocol replies are bounded; overflow fails the writer and
counts discarded bytes in `dropped_reply_bytes()`. These diagnostics are available
to the host but require host/UI integration; they are not silently a successful reply.

Close drops descriptors, discards queued replies and transfers child ownership.
Repeated close is an idempotent handoff, not a claim that cleanup has finished.
Check `cleanup_pending()` and `is_exited()` on the retained session ticket.


`encode_key` uses shared Rust function-key and modifyOtherKeys encoding, including DECCKM mode 1; `encode_paste` normalizes line endings and wraps only for mode 2004, bounding the final wire bytes to 4096. Nonzero Kitty keyboard flags remain explicitly unsupported. A real Vim run now verifies bracketed paste plus application left/right cursor movement through these encoders.

`encode_text` handles IME committed text as complete UTF-8 without bracketed-paste or modifier transforms, matching the existing Frost committed-text path; controls are rejected and nonzero Kitty flags remain explicitly unsupported.

Query behavior and protocol source evidence are documented in `../QUERY-POLICY.md`; no old-host DA2 identity is advertised.

### Bounded primary history snapshots

`Terminal::history_page(offset, limit)` returns an owned `HistoryPage` with
`revision`, `offset`, `total_rows`, `row_count`, and `text`. Offset skips that many
newest archived rows; each page is chronological. Limit is 1..128. History retains
at most 1024 compressed physical rows (each originally at most 256 columns),
evicting oldest rows. It uses shared `ScrollbackLine` and captured region effects,
not an independent ANSI parser. Only full-height primary upward LF/wrap/SU scrolls
archive rows. Partial margins, insert/delete lines and alternate output do not.
Alternate mode exposes an empty page and cannot erase primary history via ED3.
Primary ED3 clears history.

Snapshots contain archived rows only, not the current live screen. They remain
immutable under subsequent output, eviction, resize and alternate-screen changes.
Resize preserves historical physical widths; no reflow occurs and resized-away
live rows are not archived. Copy extraction joins soft wraps, separates hard
lines, strips hard-line trailing padding and omits wide continuation cells.
Selecting only a wide continuation does not invent its preceding lead character.
`HistoryPage::selection_text(sr, sc, er, ec)` uses physical-cell coordinates and a
half-open lexicographic interval; `(row_count, 0)` is a valid end sentinel. Output
is bounded to 131200 UTF-8 bytes. This is snapshot copying, not full live-screen
mouse selection or an OS clipboard integration.

### Bounded asynchronous direct-child cleanup

A single global reaper has exactly 32 slots. A slot is reserved **before** PTY or
child creation; setup failure releases the reservation. Reaper thread creation,
pidfd-open and pidfd signal-0 capability checks happen before any child is spawned.
The adapter requires default SIGCHLD disposition with no SA_NOCLDWAIT (read-only
check; it never changes signal settings). The embedding process must not install
an external reaper, call waitpid(-1), or change that disposition concurrently.

Immediately after spawn the still-owned child gets a pidfd. If that fails, PTY
handles are closed and the owned child is handed off in observe-only quarantine;
spawn reports failure, but retains the slot until actual reaping. There is no
raw-PID signalling fallback. close/Drop only close descriptors and hand ownership
to the reserved slot; they do not invoke child wait(), portable kill(), or create
per-child threads. Success means handoff accepted, **not termination confirmed**.
Each ticket remains distinct even when a reaped slot is reused.

The worker moves a child out of the table before OS operations. It uses try_wait;
only Ok(None) permits pidfd_send_signal(SIGKILL). A confirmed exit frees its slot;
wait errors or signal errors permanently remove signalling authority and preserve
observe-only ownership. Panic/poison quarantines the reaper and rejects new
spawns rather than releasing uncertain slots. A live child can remain pending
indefinitely, but cannot allocate more threads/slots; full capacity rejects new
sessions. Table locks cover bounded ownership moves, not OS calls. OS scheduling
and syscalls are not real-time guarantees.

Tests cover fixed-capacity exhaustion with never-reaped fake children, reservation
rollback, startup failure, wait/signal failure quarantine, poison/panic, ticket
reuse, and real PTY large-output exit/close/retry paths. The former unbounded
foreground wait has been removed. Descendants/background jobs remain **outside**
this ownership model; no process-group kill, cgroup containment, or process-tree
traversal is implemented. Application process exit may terminate the worker before
pending children are reaped; no process-lifetime persistence is promised.

### Unicode scalar/frame contract

The adapter uses the shared Rust parser for fragmented UTF-8 and shared
`ScreenState::write_char_in_row` for wide-pair overwrite repair. Width is
`unicode-width` scalar width, not grapheme layout. Combining marks, ZWJ and other
zero-width printed scalars are explicitly counted as unsupported with a fixed
payload-free diagnostic; they do not overwrite the preceding base cell or move
the cursor. Emoji sequences and composed glyphs are not claimed supported.

The adapter preserves frozen core 57ed89a's documented one-column truncated-wide
lead behavior: a width-two scalar is retained without an out-of-bounds
continuation. The bridge must draw this right-edge lead in its available one
column rather than claiming two visible columns. Shared resize clears truncated
wide pairs; history retains its original geometry. Full-width fits, pre-wrap at a final
column, autowrap-disabled clamping, lead/continuation overwrite, all UTF-8 split
points, and a fixed real-PTY Chinese printf sequence are covered by tests.
`unicode-test-results.txt` records 44 unit tests, 2 integration tests and strict
Clippy. This evidence validates Rust cells, not native GUI/font rendering.

### Resize and cursor validation

Resize now preflights dimensions and revision/layout counters before invoking
PTY resize, then applies shared Rust geometry only on success. Invalid bounds,
closed sessions, injected PTY errors and exhausted counters do not mutate the
frame; counters cannot fail after a successful PTY resize. Real PTY tests query
kernel winsize at 1x1, 128x256 and intermediate dimensions, and drive cursor
shape, hidden visibility and clamped position through fixed shell printf output.

Shared DECSCUSR maps 0/1/2 to block, 3/4 to underline, 5/6 to beam. The current
core does not retain a separate blink flag: blinking versus steady is not
claimed supported. Real geometry changes clear pending wrap and clamp cursors;
alternate restore recovers primary shape/position while DECTCEM visibility is
global. `resize-test-results.txt`: 47 unit tests, 2 integration tests, strict
Clippy passed. No native GUI/IME positioning claim follows from these tests.
